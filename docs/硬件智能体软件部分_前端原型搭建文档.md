# 硬件智能体系统前端原型搭建需求文档 (优化版 V1.1)

> **定位**：面向 AI 代码生成器的前端原型工程指令，请基于本文档生成一个完整的硬件智能体管理系统前端原型。  
> **建议技术栈**：React 18 + TypeScript + Ant Design 5 + ECharts (状态监控图表) + React Router 6 + Zustand (状态管理)。  
> **数据策略**：全部采用 Mock 数据与前端模拟逻辑（语音识别、设备状态变化、图像识别结果），不依赖任何后端或硬件。

---

## 一、项目概述

### 1.1 背景与目标
构建面向工业物联网的硬件智能体系统，通过 **语音/文字双通道交互** 实现对多种工业设备的智能查询、联动控制与状态监控，并融合 **图像识别** 提供“视觉+数据”双重校验，提升运维智能化水平。

核心能力：
- 多设备统一管理（灯光、电机、风扇、传感器等至少4类）
- 语音/文字指令实时控制，支持启停、开关、模式切换
- 设备联动控制（多设备组合执行）
- 模拟摄像头接入与设备类型/状态识别
- 控制结果实时反馈与语音播报

## 二、页面路由与整体布局

| 路由 | 页面组件 | 说明 |
|------|----------|------|
| `/` | `DeviceDashboard` | 设备总览（卡片网格） |
| `/control/:deviceId` | `DeviceControl` | 单个设备智能交互控制 |
| `/detail/:deviceId` | `DeviceDetail` | 设备详情与节点配置 |
| `/vision/:deviceId` | `VisionValidation` | 图像识别与状态验证 |

**全局布局**：
- 顶部：系统名称 + 导航菜单（设备列表、智能体控制等）+ 当前时间/用户信息
- 主内容区：根据路由渲染
- 控制界面/详情界面使用左右分栏布局

## 三、功能模块详细需求

### 3.1 设备总览 (`DeviceDashboard`)

#### 3.1.1 布局与内容
- 以卡片网格展示所有已接入的硬件智能体设备（Mock 数据预置 6-8 个）。
- 每张卡片包含：
  - 设备类型图标（用差异化 SVG 或 Ant Design 图标区分：网关、电机、风扇、传感器、灯光等）
  - 设备名称（如“环形线电机-01”）
  - 设备型号/描述（如“研华工业通讯网关”）
  - 状态指示点（绿色运行/红色停止/黄色故障）
  - 【开启智能体】按钮：点击后跳转至该设备控制界面 `/control/:deviceId`。

#### 3.1.2 交互
- 卡片可筛选（下拉选择设备类型：全部/网关/电机/风扇/传感器/灯光）。
- 搜索框支持按设备名称或 IP 搜索。

---

### 3.2 设备智能交互控制 (`DeviceControl`)

#### 3.2.1 布局
- 左侧：设备指令库 + 历史对话记录
- 中间：对话式交互区（指令输入与执行结果反馈）
- 右侧：当前设备实时状态面板（可选，原型可合并在中间）

#### 3.2.2 指令输入方式
**语音输入（模拟）**：
- 麦克风按钮，点击后开始模拟拾音（1.5 秒动画），之后显示“听到：‘启动环形线电机’”。
- 语音停止后自动执行指令，无需额外点击发送。

**文字输入**：
- 底部输入框 + 发送按钮，输入后按回车或点击发送执行。

#### 3.2.3 指令类型与执行
系统需支持至少 **3 种控制类型**：
1. **启停控制**：启动/停止设备（如“启动环形线电机”）
2. **开关控制**：打开/关闭设备（如“打开车间照明灯”）
3. **模式切换**：切换工作模式（如“切换散热风扇为高速模式”）

执行后：
- 对话区新增一条系统回复卡片，显示执行结果文字（如“环形线电机已成功启动”）
- 右侧设备状态面板同步更新（运行/停止、开关状态等）
- 触发 **语音播报**（使用 Web Speech API 模拟播放结果文本，无 API 时降级为文字提示）

#### 3.2.4 设备联动控制
- 在多设备选择弹窗中勾选其他设备（如“推料电机”、“传送带电机”），组合执行同一指令。
- 执行后所有联动设备状态同步刷新，对话区批量反馈结果。

#### 3.2.5 历史记录与指令库
- 左侧指令库：分类展示常用指令（如“启动”、“停止”、“查询状态”），点击可快速填入输入框。
- 历史记录：按时间倒序列出最近指令记录，可点击重新执行。

---

### 3.3 设备详情与节点配置 (`DeviceDetail`)

#### 3.3.1 顶部信息
- 设备名称、类型图标、当前运行/通信状态。
- 操作按钮：【新建对话】（跳转控制页）、【图像验证】（跳转视觉页）。

#### 3.3.2 左侧指令树
- 按功能分类的指令树（如：启动类、停止类、参数设置类、查询类），点击指令可快速执行（需确认）。

#### 3.3.3 右侧设备节点配置
- 表格形式展示 IO 节点信息：节点名称、类型（DI/DO/AI/AO）、当前值、状态。
- 数据为 Mock 静态与动态混合，刷新模拟从传感器读取数值（如温湿度显示 25.3℃ / 60%）。
- 支持手动修改部分节点值（仅前端模拟），并显示“修改成功”。

---

### 3.4 图像识别与状态验证 (`VisionValidation`)

#### 3.4.1 模拟视频流
- 页面左侧显示一个模拟的“实时画面”（使用 Canvas 或图片占位，显示工业设备场景）。
- 可通过下拉切换不同场景图（如“电机区域”、“传感器区域”）。

#### 3.4.2 识别结果叠加
- 在画面上绘制边界框和标签（用 Mock 数据，如框出电机并标注“电机-001 [运行]”）。
- 下方展示识别结果表格：设备名称、识别状态、置信度。

#### 3.4.3 双重验证
- 系统将图像识别结果与当前设备上报数据比对：
  - 若一致 → 绿色提示“视觉与数据一致，状态正常”。
  - 若不一致 → 红色告警（如“视觉识别电机运行，但数据上报停止 → 异常告警”），并记录在异常日志中。
- 提供“刷新识别”按钮，重新模拟识别结果。

## 五、视觉与交互规范

- **主色调**：科技蓝 + 深灰背景，状态颜色：运行绿(#52c41a)、停止红(#f5222d)、故障橙(#faad14)。
- **字体**：系统默认无衬线，标题加粗。
- **交互**：语音输入按钮有脉冲动画；设备卡片 Hover 浮起；指令执行时对话区自动滚动到底部。
- **反馈**：所有操作结果使用 `message` 全局提示，执行成功伴有语音播报（模拟）。
- **布局适配**：主要桌面端 1920×1080，移动端可后续优化。

## 六、非功能性需求（原型阶段）

- 所有模块纯前端模拟，无任何硬件或后端依赖。
- 语音输入使用 `setTimeout` 模拟，语音播报使用浏览器的 `SpeechSynthesisUtterance`（需浏览器支持，不支持则忽略）。
- 图像识别使用静态图片 + CSS 定位绘制框，通过 Mock 数据模拟结果变化。
- 状态管理使用 Zustand 统一维护设备列表、当前控制对话、识别结果等。
